## 14. Open decision: what position a `contains` link must open

**Status: RESOLVED — the gate was wrong, not the component.**

**Resolution.** `groundOf()` already computed the far end's declaration position
(`declarationKey`, LSP 0-based, identifier column) but then chose `stored` for
every row: `key: stored ?? declarationKey`. Under Law A a declaration row's
governing position IS the declaration, so the gate was comparing a correct card
against the wrong reference. The grounding now reads
`declaration ? (declarationKey ?? stored) : (stored ?? declarationKey)` — a usage
row keeps the stored call-site line (that IS its governing position), a
declaration row uses the declaration. Measured: `m42-rich-hover` 68/71 → **70/71**,
and the oracle's own `sectionContainment` predicate flipped to true.

**The rule this leaves behind:** when a card is right and a gate says it is wrong,
check which REFERENCE the gate chose before touching either. Every comparison has
two sides and only one of them was reviewed.


Two laws govern the `contained` block of a hover card:

**Law A — the address rule (adopted this campaign, gated in T3/§6).** An outgoing
or declaration row opens the far end's index-stored declaration; a stored
call-site line is never turned into a link in another file's coordinate system.
This ended the defect where `instantiates [Greeter]` opened `greeter.ts:4` for a
site in `app.ts`.

**Law B — `H2/R4-LAW-CONTAIN` (written before Law A).** Every `contained` link
equals the index-stored location of the `contains`/`exports` row it renders.

**Measured on the H2 fixture, `Greeter` contained in `App.java`:**
```
rendered link     App.java:5:6
stored row key    App.java:6:0
callSite record   {"kind":"declaration","file":"…/App.java","line":6,"note":"this is the calling symbol's declaration, not the call site"}
```
**These disagreed by a whole LINE, not by a column.** An earlier reading of this
table — that `5` and `6` were the same line in different bases — was tested and
is WRONG: narrowing the comparison to `file:line` still reports `0/1`, so the two
keys name different lines under whatever base each one uses.

That leaves exactly two possibilities, and they are cheap to distinguish:

1. **the gate's stored key is off by one** for containment rows (the `callSite`
   record says line 6 and the key says 6, so if the component's key is 1-based it
   is rendering line 5 — one BEFORE the declaration), or
2. **the component's containment link is off by one** — it points at the line
   before the declaration it means to open.

**Do not "fix" this by relaxing the law.** The first attempt at that — matching
containment on `file:line` because the stored column is a placeholder `0` — was
reverted after measurement showed the line itself was the disagreement. Relaxing
a comparison to accommodate an off-by-one is how a gate stops being able to fail.

**Next step:** print the raw `CardLink.key` and the raw stored `containmentRowGrounds[].key` side by side with their base conventions, and see which one moves
when the declaration line moves. One of them is wrong and the gate is the only
thing that noticed.

### 14.1 What is left in `m42-rich-hover` (70/71): the oracle, not the card

The card is correct and both section laws pass. The one red check is `H2/M`, the
meta-check that the mutant oracle HOLDS on the correct component — it fails
because five of the oracle's own predicates are still written to the PRE-Law-A
world, the same mistake §14 records on the section law:

```
position:false  containmentInItsOwnBlock:false  label:false
sectionUsage:false  sectionConnected:false      (count/edge/sectionContainment: true)
```

`position` is the clearest: it requires the usages links to include
`App.java:${appCallLine - 1}:0` — a **line-start column 0** — while the component
correctly serves the precise call site `App.java:12:23`. Law A (the source-side

**Do not fix this by loosening the predicates.** They are the thing that convicts

is to re-state each predicate in the address rule's terms and re-check which
mutants each one catches — `containmentInItsOwnBlock`'s comment already records
one precedent where the old one-sided form went false on a CORRECT component and
"marked every mutant caught for free".
