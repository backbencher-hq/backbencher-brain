# M12 Validation Evidence

This directory is version-controlled product validation evidence for the
M12 Per-Analyzer AST Perfection milestone.

M12 verifies each of the 41 wired language analyzers **alone, one by one**,
in priority order (JVM → .NET → Web → Systems → Functional → Dynamic →
Data/Shell), against a bar of pure AST extraction, optimal time complexity,
complete symbol/relationship contracts, differential ground truth,
real-corpus validation, and dedicated documentation.

## Layout

- `schemas/` — machine-readable schemas (ground truth, observed facts,
  differential results), retagged for M12 from the M11 set.
- `fixtures/<language>/` — positive and negative fixtures per analyzer.
- `ground-truth/<language>.json` — independent expected facts per analyzer.
- `results/` — observed facts, differential results, regex census, and
  complexity measurements.
- `corpus-manifest.json` — per-analyzer corpus targets and pinned revisions.

## Rules (inherited from M11)

- Expected facts come from source, compiler, language-service, IDE-index, or
  manual-audit authority — never generated by the analyzer being measured.
- Every failure records the earliest failing layer and a minimized fixture.
- Fixes must be language-general and pass at least one positive and one
  negative fixture for the affected grammar/relationship.
- No project-specific analyzer filters are permitted.
- Precision, recall, false-positive rate, false-negative rate, and unknown
  rate are reported separately; a passing exit code alone is insufficient.

## Regex census

`script/m12/regex-census.ts` produces an AST-driven (tree-sitter) census of
every regex literal and `RegExp` usage across all 41 analyzers — never a
text-grep approximation. `script/m12/verify-regex-census.ts` machine-checks
the census: it fails on any regex usage in source that is missing from the
census, and on any census entry that is not classified
(`replaceable` / `unavoidable` / `unclassified`) with a location.

Baseline census output: `results/regex-census.json`.

## Per-analyzer docs

Every analyzer issue ships `docs/analyzers/<lang>.md` from the
template at `docs/analyzers/TEMPLATE.md`.
