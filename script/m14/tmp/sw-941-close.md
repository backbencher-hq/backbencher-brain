**CLOSED — both halves, and SW-G's own sentence is now true on both sides: "unresolvable stays silent."**

**1. The analyzer no longer invents an owner.** The owner expression was `parent?.ownerName ?? parent?.name`; when the enclosing symbol is the initializer itself, `parent.name` is the literal string `constructor` — not a type — so the lane published `instantiates constructor -> constructor` (source and target both `constructor`, `isSelfInit`, conf 0.95). The rule implemented now is the one the issue wrote down: the owner is the parent's `ownerName` when the parent is a MEMBER symbol, and the parent's own `name` only when the parent IS the type (deinit/subscript/observer bodies have no symbol of their own, which is the only reason the fallback exists).

**2. The truth side no longer publishes the dangling call.** The oracle's SW-G mirror only set `consumed` on the resolvable branch, so the unresolvable case fell through to the generic path and emitted `calls -> init`. `init` is not a name in this vocabulary (constructors are literally `constructor`), so it is the "dart DT-A" dangling target SW-G was written to remove. `consumed` is now set whether or not the owner resolves, so there is **no `instantiates` and no `calls -> init`** for an unresolvable delegation — on either side.

Both halves are directly pinnable and are pinned: fixture `swift/error-recovery-nominal` carries a recovered container plus a delegating initializer and asserts the **absence** of both edges, and the two reverting mutants (invented owner; truth-side fall-through) are CAUGHT (`swift/error-recovery-self-owner-target`, `swift/error-recovery-dangling-init-call`).
