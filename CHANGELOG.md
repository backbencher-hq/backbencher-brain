# Changelog

## 0.2.3 — the JavaScript and TypeScript receivers, and an answer that names its project

Two lines of work, both verified on the tree that ships.

### JavaScript / TypeScript: a member call is never resolved by tie-break

Fifteen commits close the receiver and binding defects in the two analyzers that most
projects actually use. The theme is that a name match is not a resolution:

- **the receiver is typed or withdrawn** — a member call is never resolved by letting a tie
  break choose among candidates; when the receiver's type cannot be established the edge is
  withdrawn and counted instead of guessed;
- **the constructor receiver** — three instruments could not see it, and the edge it was
  producing was wrong;
- **the wrapped receiver** — a cast that is not a wrapper was being read as one, producing
  one more misbinding;
- **a guard that read as a guard and guarded nothing** — the arm re-run now names the
  analyzer that ships;
- **the differential states the bound it cannot cross**, rather than implying coverage it
  does not have.

Two commits in this set are rep**airs rather than features**, and are the reason the others
are trustworthy: a hook had reformatted `real-typescript-analyzer.ts` wholesale (3,134
semicolon lines back to 34), and a store census gate had passed with the feature deleted.
Both are recorded because a gate that passes on a deleted feature is worse than no gate.

32 of 32 JavaScript/TypeScript verification gates pass on this tree.

### MCP: every answer declares the project it answered about

`bb` can be started with `--dir X` while the caller works in Y. It then answered about X with
no warning, and a symbol that exists only in Y came back as `totalMatches=0` — which reads
exactly like "that symbol does not exist". Measured: a server pointed at one project answered
`no results for "alphaOnlySymbol"` with nothing saying which project it had consulted.

Every answer now names its project: JSON answers gain a top-level `project` field, text
answers gain a trailing `[project] <root>` line beside the existing `[match-set]`. Nothing is
re-rooted — the silent wrong answer is made visible, which is the part that matters.

A JSON **array** payload is left byte-identical: it has no place for a `project` field, and
breaking a well-formed answer while adding provenance would be the one thing this must never
do. The suite asserts the payload shape, not only the wording: object gains `project` and
stays parseable, array is unchanged, double-stamping does not double the line.

CHANGELOG grammars/`, and `benchmarks/` is not among them. Its commits are in history because

## 0.2.1 — cross-language stops flagging two TypeScript files as different languages

Found by verifying the PUBLISHED 0.2.0, not by any gate, and it is exactly the class of defect
0.2.0 was meant to end: a fresh index of an all-TypeScript project still held ONE row with
`is_cross_language = 1` — a `calls` edge from `src/app/dashboard/page.tsx` to
`src/lib/util.ts`. Both endpoints are TypeScript. Because the flag is a STORED COLUMN, every
reader (`bb_graph`, `bb_impact`, `bb_cross_language`) reported a false cross-language edge, so
the 0.2.0 write-time refusal was correct and still not sufficient.

The cause was a LABEL comparison. `.tsx` has its own grammar id (`tsx`) while `.ts` is
`typescript`, so the seven queries that ask "do these two endpoints have different languages?"
answered YES for two TypeScript files. Every one of those seven was wrong the same way.

The fix normalises the COMPARISON into language families — `tsx`≡`typescript`,
`jsx`/`mjs`/`cjs`≡`javascript` — rather than rewriting the stored ids, because those are real
grammar ids the parsers need. A post-pass also CLEARS a stored flag whose endpoints are in the
same family, so an existing index is repaired by re-indexing rather than needing a rebuild.

Deliberately NOT flattened: `typescript` and `javascript` stay different languages, because a
`.ts` file calling into a `.js` file is a genuine cross-language edge. The gate pins both
directions, since a fix that silenced the false row by flattening everything would delete a
real feature:

  · `.tsx` → `.ts` must NOT be cross-language;
  · `.ts` → `.js` must STILL be cross-language.

### Orphans: the FILE rule honours the same policy

Also caught by verifying the published build: `src/polyfills.ts` was correctly suppressed as
SYMBOLS and still reported as `orphaned_file`. A side-effect file has no referencing symbol and

(`suppressedByReason.unreferencableByDesign`). On the fixture the published build reported

Gate `script/m13/verify-cross-language-family.ts`, 8/8 PASS; `verify-orphan-by-design.ts`, 22/22

## 0.2.0 — TypeScript resolves, the backfill finishes, and the exit is deterministic

Eight defects reported after 0.1.9, each REPRODUCED before it was fixed and verified at the
level the user observes — not only by a unit gate. That distinction is the theme of this
release: three of the 0.1.9 fixes were correct in isolation and dead in the product, because
they were verified on a helper instead of on the path a user runs.

### TypeScript — the launch blocker

`@/*` is the DEFAULT import alias in Next.js, Vite and Create React App. Nothing read
`compilerOptions.paths`, and any specifier starting with `@` was treated as an npm package
scope, so every alias import was unresolved: 80 of 80 alias imports lost on a real Next.js
app (74.1% of internal imports), against 28 of 28 relative imports resolved.

Three layers had to agree, and fixing one looked like success twice:
  · a new `path-aliases` module parses `compilerOptions.paths` with TypeScript's semantics
    (longest pattern wins, one `*`, exact patterns, baseUrl, fallback targets);
  · the indexer persists the aliases to `brain_project_meta` and stops filing an alias
    import as an npm package (`brain_import.is_external`);
  · BOTH specifier resolvers — `import-resolution` (the stored graph) and `dependencies`
    (the view's own resolver) — became alias-aware.
Before/after on a two-file fixture:
  `{'path': '@/lib/util', 'external': True,  'resolution': 'unresolved'}`
  `{'path': 'src/lib/util.ts', 'external': False, 'resolution': 'resolved'}`

An UPGRADE detail that would have hidden the whole fix: the aliases were persisted only when
files were reparsed, so upgrading 0.1.9 → 0.2.0 and running `bb index` on an UNCHANGED project
did nothing (`aliases` never written, and the old `is_external` flag still marking the import
external). Both are fixed — the aliases are written on every run, and an alias-shaped specifier
is resolved on the spot so a stale flag cannot outlive the upgrade. Verified by installing
0.1.9 from npm, indexing, upgrading to 0.2.0 and re-indexing with no source changes.

### Embeddings — the backfill actually finishes

A 422 content-safety rejection now isolates the refused input and the run completes.
The 0.1.9 fix was DEAD CODE: it caught a 422 from `embedMany`, but `embedMany` swallowed the
422 and returned `[]`, so the catch never fired. A unit test of the bisection proved the
algorithm worked while the wiring did nothing ("400 embedded, 55,185 missing"). `embedMany`
now re-throws a 422 on the provider-only path, the tolerant pass reconciles engine state
(so rows are labelled with the right model), and the reconcile result carries `rejected` —
distinct from `failed` (provider down) and `invalid` (malformed response).

### `bb index` exits when it is done

The command printed its whole report and then sat there ("i had to press ctrl c after at
least 2 minutes"). `exitWhenDone` ends it deterministically after stdout drains; the watchdog
is `unref()`d so it never delays a healthy run and can only cut short a real hang. The root
handle was NOT reproduced locally, so the guard does not claim to name it —
`BB_EXIT_DIAGNOSTICS=1` prints what was still open for the next report.

### Honest lists

- **Dependencies**: the 0.1.9 page budget was allocated greedily, so a row late in the
  ranking returned `dependenciesTotal: 89` beside `dependencies: []`. The allowance is now
  split fairly (divided by the rows still to come AND the two lists each carries, floor one
  entry per list), and an exact-file query — one row — still lists every edge.
- **Cross-language**: the 0.1.9 fix filtered the `bb_cross_language` PROJECTION while
  `is_cross_language` is a STORED COLUMN that bb_graph, bb_impact and bb_visualize read
  directly — so the noise left one surface and stayed on the others ("bb_graph N still
  exposes 85"). The refusal moved to the write: a flag is stored only with evidence (an
  analyzer assertion or a real bridge mechanism), never on a `name-resolution` spelling
  collision. The row is still stored and its bridge still says `name-resolution`.
- **Orphans**: bundled JS, Makefile/CMake/Dockerfile targets and polyfills/shim files are now
  suppressed as unreferencable by design, and counted in
  `suppressedByReason.unreferencableByDesign`. A missed orphan leaves cleanup on the table; a
  false one invites an agent to delete live build configuration.
- **Health status**: an EXPLAINED shortfall (a deliberate skip, or a file left alone because
  it was unchanged) no longer derives `incomplete` beside a recorded `complete`. The
  derivation now keys on the UNEXPLAINED shortfall; a genuine loss still fails closed.
- **`bb_ask`**: a flat ranking caused by low coverage now distinguishes a coverage gap from a
  PROVIDER-LIMITED backfill, and says that no scoring change would make those vectors more
  separable. Telling a rate-limited user to "run the backfill" is useless advice.

Verified before tagging: `npm test` (15/15, 21/21), `verify:fast` (22 gates, exit 0), the full
fixture corpus (all pass), `tsc --noEmit`, `npm run build`, and all seventeen gates under
`script/m13/`.

## 0.1.9 — the tool stops asserting what it cannot see

Ten defects reported after 0.1.8, fixed across three tiers. The unifying theme is
the one the external review named: a tool that states more than it can substantiate
is worse than a smaller honest one. Every fix below is pinned by a gate, and where
the defect was reproducible the gate was proven RED against the old code first.

### Embeddings — the reason coverage sat at 20.7%

- **A content-safety refusal no longer stalls the backfill.** A 422 rejects the
  whole *request* although the fault is one input, so one snippet failed its batch —
  and because that snippet sat in every retry of that batch, the run made no further
  progress: measured as "embedded 950 symbols, then stopped with 44,250 still
  pending". The reconcile path now bisects on a 422, isolates the refused text and
  embeds everything else. Refusals are counted in a new `rejected` counter, distinct
  from `failed` (provider down) and `invalid` (malformed response). A 429 is
  deliberately NOT treated as per-item: permanently skipping good text would hide an
  outage.
- **`BB_EMBEDDING_TIMEOUT_MS` now raises the wait ceiling.** It was
  `min(providerBound, 2000)`, so the 2 s read-tool default was also a hard cap and
  `15000` still waited 2000 ms, then silently answered from the 50-dimension local
  space. Unset keeps the fast default; an explicit value wins (capped at 60 s).
- **Health and doctor agree on BACKFILL PENDING.** One boolean answered two
  questions: "may a vector answer be presented as the configured space?" (the 5%
  floor) and "is the backfill finished?". At 20.7% coverage with 43,000 symbols still
  missing, the floor said nothing was pending while doctor promised health would
  report it. The two are now separate. Health's last-run count also carries its
  timestamp and the live coverage beside it, so a stale persisted number cannot read
  as current.

### Honest counts

- **Unchanged files are no longer counted as skipped files.** `skippedFiles`
  incremented for both a >5 MB rule skip and an unchanged file, so a 1,973-file
  incremental run reported `skippedFiles=1973` beside the honest count of one. Now
  split, with both in the denominator and both in the health message.
- **Dependency pages are bounded by rows and exclude test files.** `limit` bounded
  file rows while each row could carry 100 dependencies plus 100 dependents, so a
  page could reach ~10,000 entries (measured: 10,923 lines before host truncation).
  A page row budget now bounds the whole answer; `_test.go` files are filtered,
  counted in `testFilesExcluded`, and restorable with `includeTests: true`.
- **Test mapping no longer spends its link cap on duplicates.** The same test could
  occupy many of the 20 slots through repeated stored edges: 16 repeats of
  `TestModuleParamValidate:107` read as sixteen tests. Links are folded to one per
  (symbol, test), strongest evidence wins, and the fold is counted.

### Refusing to accuse

- **Cross-language facts exclude minified assets and name-only collisions.** A row
  into `openlayers/ol.js` matched identifiers a minifier had minted (`N`, `to`,
  `r`) — a coincidence of the alphabet, not a bridge. 110 of 122 edges were that
  shape, and `bb_cross_language N` alone reported 85. Both classes are refused and
  counted (`excludedAssetRowCount`, `nameOnlyCandidateCount`).
- **A symbol with refused usage evidence is unresolved, not dead.** Orphan detection
  published 4,570 candidates, including live dynamically-registered functions, beside
  a "REFUSED EVIDENCE" note. A false orphan is dangerous — an agent deletes live
  code — so such symbols are now suppressed as `usageUnresolved` and counted. The
  analyzer's inability to see dynamic registration is still a declared limit; what
  changed is that the tool no longer asserts death where it merely lacks evidence.
- **A dialect the grammar cannot parse is declared, not called a file error.**
  `.less` and `.sass` route to the CSS grammar, which has no `@variable`, mixin
  guards or indentation, so it warned about correct constructs — reported to the user
  as "24 Font Awesome LESS/SCSS syntax errors". Those are now counted as declared
  dialect limits, with the raw warnings still stored.

### The manual

- **`man bb` no longer carries a version or a date.** The header read
  `"September 2026" "bb 0.3.0"` while the package was 0.1.8 — eight releases stale,
  because the hand-maintained header had to be edited on every release. The manual
  documents behaviour, not a release; `bb --version` answers "which version". A
  release no longer requires touching it.
- Two stale claims fixed with it: the `index` entry told the reader `--force`
  rebuilds vectors after a model change (contradicting the EMBEDDING SETUP section of
  the same page, which correctly describes the in-place reconcile pass), and
  `BB_EMBEDDING_TIMEOUT_MS` is now documented with its real rule.

### bb_ask

- A non-discriminative ranking now explains itself — how many candidates sit inside
  the margin, the margin, the top score, the coverage that limits it, and that the
  configured-model backfill is what raises it — instead of only withholding a number.
  `totalMatches` beside `limit` remains the candidate bound, already labelled.

Verified before tagging: `npm test` (15/15, 21/21), `verify:fast` (22 gates, exit 0),
the full fixture corpus (all pass), `tsc --noEmit`, `npm run build`, and the ten new
gates. One regression was caught by `npm test` during this work — the first cut of
the content-safety fix routed the whole reconcile pass through the new path and
bypassed its rate-limit circuit breaker — and was fixed before release rather than
after.

## 0.1.8 — hotfix: an existing index is indexable again

Fixes a P0 that shipped in 0.1.7 and made every project with a pre-existing index
unindexable:

    storeResults failed {"error":"no such table: brain_project_meta"}
    a batch failed to store, some files may be missing from DB

The Go module-identity work reads `brain_project_meta`. `ensureProjectMetaTable()`
was added for it but wired into only the FRESH-database path; the existing-index
open path (`src/brain/database.ts`) called its siblings and not this one. Every
index built by an earlier bb therefore had no such table, the read threw inside
`storeResults`, and the whole batch was lost — files silently missing from the DB.

Fixed by calling `ensureProjectMetaTable(raw)` on that path too. Additive and
idempotent: a conforming database pays one `CREATE TABLE IF NOT EXISTS`.

**Workaround for anyone still on 0.1.7:** remove the project's index and re-index.
`bb index --force` does NOT help — measured, still fails.

**Why the previous release passed its gates:** nothing exercised "an index created
by the previous version, opened and indexed again". Every gate and fixture built a
fresh index, so the broken path was never entered. `script/m-fix/verify-old-index-compat.ts`
now covers it, functionally: build the DB, DROP `brain_project_meta` to stand in
for a pre-0.1.7 index, re-open (the migration), add a file, re-index, and require
the new symbol to exist — asserting the row rather than the log, because a
swallowed error would pass a log check. Proven in both directions: with the fix
disabled the gate reports `helper rows=0` and fails; restored, it passes.

Verified before tagging: `verify:fast` 22 gates exit 0, `tsc --noEmit`,
`npm run build`, and the upgrade gate's RED/GREEN control. Reproduced against the
published 0.1.7 artifact first — a table-less DB plus one new file gave exit 1 and
eight error lines; the same scenario on this tree gives exit 0, zero errors, both
files stored.

## 0.1.4 — the security tool reports leads it can defend

Owner-facing release. Every claim below was verified on the release tree: `npm test`,
the three security gates, `verify:fast` (all gates), the full fixture corpus, and the
packaged-tarball smoke. The in-flight TypeScript and C++ analyzer work present in the
tree at the time of this build is included; those two lanes were not finished, so their
claims here are limited to what the gates measured.

- **`bb_security` is a lead generator, not a vulnerability scanner.** It reports
  lexical source→sink token pairs over the indexed symbols, and the description,
  docs and answers all say so. A lead is stored when a source expression reaches a
  dynamic sink argument in the same symbol, with the rule id, the source and sink
  lines and the assignment reach path. Parameterized, constant-argument,
  comment-only and test-file cases are excluded. What it does not do is stated in
  the tool description and the docs: no data-flow analysis, no cross-symbol
  propagation, no sanitizer modelling, no proof of exploitability. Leads require
  manual validation.
- **Unsupported languages are declared, never a clean zero.** A project written in
  JSON, YAML, SQL or any language with no executable source model now answers with
  "not scanned by bb_security (no executable source model): …" instead of a
  confident-looking empty result. The tier registry is the source of truth, and the
  declaration is per project, read from the files that were actually indexed.
- **The retired token cross-product is replaced, not deleted silently.** The M72
  spec engine writes `brain_security_flow`; the legacy `brain_taint_flow` writer
  runs only under `BB_SECURITY_LEGACY=1` for one release. A pre-M72 row can no
  longer be re-presented as a lead.
- **Live leads are paginated and declared.** `limit` is a live page size (default
  50, max 200) and `offset` pages live leads only; the answer states the page, the
  page size and the declared total, so a page is never mistaken for the whole set.
  `history` keeps its own bounded run page.
- **JavaScript: the receiver-owner and source-attribution work.** A named function
  expression rebinds the uses walk's source; receiver types are scoped to the class
  that declares them; emitted endpoints are real names (measured zero invalid on
  70,157 rows); the `implements` clause is proven grammar-fixable and measured, not
  wired; census artifacts behind the receiver-owner audit tables are tracked.
- **Go: source attribution through closures, func literals and package vars.** A
  channel read in a package-scope closure belongs to the closure's variable; a
  func-typed package var is a call target and its calls were being dropped; the
  `references` edge attributes through a func literal to the owning package var;
  package-scope `instantiates` attributes to the declaration rather than `global`;
  the inherited const type (GO39) and package-scope func-type var (GO40) defects
  are fixed; the dangling-source table is split by resolver because 6,723 was two
  measurements.
- **PowerShell: the type reader tests the argument node, not its text.** A
  `New-Object` dynamic type name is decided by the argument node, because the
  grammar wraps a bare `$t` and a single-quoted `'\$literalType'` identically and
  only the interpolated form carries a `variable` node. Preference variables and
  property symbols are filtered from `contains`; `New-Object` no longer publishes a
  `calls` edge to itself; Verb-Noun cmdlet calls are not user functions.
- **`project-stats` counts symbols per file.** `COUNT(s.id)` over a `LEFT JOIN`
  counted the language row once per symbol, and one row for a file with no
  symbols. The subquery counts per file first.
- **Release gates.** `prepack` and `prepublishOnly` run the dist-integrity check;
  the packaged-install gate packs the tarball, installs it into a temp prefix, runs
  `--version`, runs a real index asserting the summary/path/run lines, and
  `bb setup reset`. Docs and website build clean.

Evidence for this build: `npm test`, the three security gates (52/52, 58/58, 22/22),
`verify:fast` (22/22 gates), the full fixture corpus, the website typecheck and
build, and the packaged-tarball smoke.

## 0.1.3 — UX overhaul

Owner-facing release. Everything below was verified on the packaged tarball before
publication.

- **Embedding setup is key-first.** Paste the API key (hidden, never echoed — the
  old reader leaked the key interleaved with stars), the provider is detected from
  the key, the embedding models that key can use are listed, and the user picks one
  or types a model id. The choice is validated with a live `/embeddings` probe
  before saving. A failed probe keeps the user in the menu (retry / change model /
  change key / skip) instead of dropping out with nothing saved — the loop that
  made every `bb index` re-prompt. OpenRouter is no longer advertised as an
  embedding provider (its catalogue lists none); the custom base-URL + manual model
  path remains.
- **`bb setup` can be re-run and `bb setup reset` removes** the saved provider, key
  and model (and the skip marker) without touching the index. Changing the model
  is reconciled by the next `bb index`: stored symbols are re-embedded in place
  with the new model (no re-parse) and superseded rows are deleted, so an
  unchanged index no longer keeps old vectors. The repair is incremental and
  provider-only: each `bb index` sends only symbols still missing the configured
  model, and a rate-limited provider keeps existing vectors and reports the
  remaining count so a later run continues from there. `bb index --force` remains
  the full parse rebuild. The skip message names both paths.
- **Asymmetric NVIDIA embedding models work end to end.** Nemotron 3.5 embed
  models require `input_type` and reject requests without it; bb now sends
  `passage` for stored symbols, `query` for search queries, and `passage` for the
  setup probe, so `nvidia/nemotron-3.5-embed-8b` on NVIDIA NIM indexes and
  searches. The docs note that OpenRouter's free route has a small daily request
  cap, so bulk embedding should use the NVIDIA NIM endpoint directly.
- **Every post-parse phase is visible and timed**: cross-file/cross-language
  resolution, enrichment (with pattern breakdown and declared dangling/unresolved
  counts), gravity, taints (with flow count), health, integrity, vector blobs and
  planner stats. Long phases print a heartbeat.
- **The completion report is richer:** index database path (with the exact `rm -rf`
  to remove it), DB/WAL size, cross-language edges, taint flows, relationships
  explained + patterns, worker count, per-phase timings and wall time.
- **Embedding drain is live:** vector progress, and on a provider 429 the retry
  attempt, countdown and growing backoff (5s, 10s, 20s, 30s cap) instead of a
  silent wait that looked like a slow indexer. The engine also logs the rate limit
  while it happens.
- **`bb_graph` edges expose the stored enrichment "why"** as
  `metadata.enrichment` (`role`, `pattern`, `layerFlow`, `criticality`,
  `frequency`, `inferredAt`).
- **Release gates:** `prepack` refuses a dist whose chunk references do not
  resolve; a packaged-install gate packs the tarball, installs it, and runs
  `--version`, a real index (asserting the summary/path/run lines) and
  `bb setup reset`. Test evidence for this build: `npm test`, `verify:fast`
  (20 gates), 1,776/1,776 fixtures, a PTY mock-provider setup run, and the
  packaged-tarball smoke.

## 0.1.0 — first public release

The first public release of Backbencher Brain (`backbencher-brain` on npm, `bb` on
the command line). Everything below is what a fresh `npm install -g @backbencher/brain`
gives you. The section still headed **Unreleased** further down was written against
internal builds and ships in this release; read it as the detailed change record
behind this summary.

### What ships

- **16 MCP tools**, served over stdio to any MCP host (Claude Code, Cursor, VS Code,
  Zed, and anything else that speaks MCP): `bb_search`, `bb_ask`, `bb_analyze`,
  `bb_graph`, `bb_impact`, `bb_patterns`, `bb_security`, `bb_doc`, `bb_visualize`,
  `bb_migrate`, `bb_cross_language`, `bb_edit`, `bb_index`, `bb_health`,
  `bb_annotate`, `bb_annotations`. Tool descriptors are the same for the CLI and the
  MCP server, and `docs/data/public-tools.json` is generated from the executable
  registry so the catalog cannot drift from the tool that answers.
- **50 language analyzers**, from TypeScript/JavaScript, Python, Go,
  Rust, Java/Kotlin/Scala/Groovy and C/C++ through to Haskell, Clojure, Clean, Erlang,
  Julia, Nim, Solidity, HCL/Terraform, Vue, Svelte and more. TSX, Sass and Terraform are
  aliases of the TypeScript, CSS and HCL analyzers, not extra languages; the editor lane
  covers 49 of the 50 (Objective-C is excluded because `.m` is shared with MATLAB) and 48
  carry recorded in-editor evidence. The list is the `SUPPORTED_LANGUAGES` map in
  `src/ast/engine.ts`; the site reads the same map.
- **A CLI with 14 commands**: `bb index` (build/inspect the index), `bb search`,
  `bb mcp`, `bb setup`, `bb stats`, `bb status`, `bb health`, `bb doctor`,
  `bb projects`, `bb onboard`, `bb tool`, `bb upgrade`, `bb version`, `bb help`.
- **An LSP server** (`dist/lsp/server.js` over stdio; the editor extension launches it) for the launch languages recorded in
  `src/lsp/launch_languages.ts` — hover, definition, references, document symbols,
  workspace symbols, call hierarchy. The launch set is extended only through the
  recorded wave protocol, so the set here is what the gates prove, not a promise.
- **Local-first by construction.** The index is SQLite, one database per project,
  outside your repository (`bb stats` prints the path). Nothing is uploaded, there is
  no account, no telemetry and no hosted service; semantic search needs a local
  embedding provider you choose (`bb setup`).
- **Edits that declare their limits.** `bb_edit` does AST-bounded write/update/
  insert/delete/refactor with pre-image checks, dry runs, batch atomicity and a
  formatter step that reports what it actually did. Every read surface carries a
  freshness block rather than quietly answering from a stale index.

### Install

```bash
npm install -g @backbencher/brain     # primary path, Node.js >= 18
bb --version
bb setup                              # optional: semantic search provider
bb index /path/to/project
```

`curl -fsSL https://backbencher.cc/install.sh | bash` and
`irm https://backbencher.cc/install.ps1 | iex` remain as alternatives: they install
the same npm package, and fall back to a checksum-verified GitHub release binary only
when npm is unavailable. Pin a version with `VERSION=0.1.0` in front of either script.
Windows, Linux and macOS are supported; the native modules (`better-sqlite3`,
`web-tree-sitter`) build through npm's normal platform support.

### Known limits, stated rather than buried

- Node.js 18 or newer is required; there is no bundled runtime.
- Parsing and analysis are static. Nothing here executes the code it reads, so a
  clean report is not a proof of correctness or security.
- The LSP serves the languages in the launch set; other indexed languages still get
  the MCP/CLI surfaces but not editor features.
- Semantic retrieval quality depends on the embedding provider you configure; the
  lexical/graph surfaces work without one.
- `npm upgrade`/`bb upgrade` move you to the next published release; the index schema
  migrates in place and is never wiped by an upgrade.

### Version numbering

`0.1.0` is the first public version. Earlier internal builds counted up to `0.3.0`,
and a separate pre-release binary product used `1.0.x` version numbers; neither is
continued here. No `1.0.x` artifact was ever published to npm, and the `1.0.x`
installer line is retired — the installers in this repository install
`backbencher-brain` from npm.

## Unreleased

### The editor surfaces stopped disagreeing with each other

Four surfaces answer "who uses this symbol": the hover card, `bb/graph` `mode:"usages"`
(the hub), `textDocument/references`, and the hover's own `connected:` line. Measured on a
real index over real stdio, one symbol produced four numbers — `greet` reported 6 usages in
prose while its own connections line listed 3 callers, the hub listed 6 caller groups, and
references returned 7 locations. Each number was individually defensible: they counted
different things, and none of them said what.

They now count one thing and say so. A **usage site** is a stored relationship row whose
target is the symbol and whose kind is not a declaration containment, owned in one place
(`src/lsp/relations.ts`); a **count** is a count of served positions, and the unit sentence is
the owner's single copy quoted by every surface. The hover's count equals its rendered rows
plus a declared remainder; zero is stated rather than omitted.

Three separate lies were removed to get there, each found only because a human read the
surface:

- **The hover's "usages" list was not usages.** `greetAll` has zero callers and rendered
  "3 usages" listing its own class (`Greeter`) and its own callee (`greet`). Declaration
  containments now render in their own labelled section and never in the usage list or the
  connection summary.
- **The hub served the owner-family cascade as callers.** A method with **zero** callers
  answered six caller groups — every class member's referrers plus the class's own
  instantiators — so "who calls this" listed symbols that never call it. Cascade rows are now
  excluded **and counted** per bucket (`selfReferentialRows`, `declarationContainments`,
  `ownerFamilyRows`), with `callerCandidateRows` on the payload so every excluded row is
  accounted for. The naive fix — drop everything not adjacent to the root — was measured and
  rejected: it deleted the hub's legitimate transitive call tree. The law that satisfies both
  is that a deeper row is served only when it extends an already-served chain.
- **The class's caller list carried a member's own call**, re-attributed to the class. It now
  equals the class's usage sites.

`script/m55/verify-relations.ts` grew four cross-surface assertions (`R3b`) that pin the
agreement on the wire: a zero-caller symbol answers zero from hover, references and the hub;
an empty answer is empty *by a declared filter* whose counts close the row arithmetic; a
symbol with callers reconciles as groups = usage places + the declared unlocatable referrers.

### A position a surface could not know is no longer shown

Three classes of invented position, all found by reading rendered surfaces:

- **The hover served stored call-site lines past the end of the source.** A three-line file
  with rows stored at lines 40 and 41 rendered two usage links that opened past the file.
  The hover now applies the same line bound `textDocument/references` applies
  (`createPositionMapper(text).lineTexts.length`), refuses to serve such a row, and declares
  the count: *"usages omitted — N stored rows name a call-site line past the end of the source
  file"*, with `data.omittedUsageRows`. Measured before/after: collector sites 2 → 0,
  `omittedUnresolvable` unchanged at 2. The agreement is gated, not described.
- **Call hierarchy listed the root as its own caller and callee**, pointed every `fromRanges`
  entry at a declaration instead of the call site, and threw `-32603` when a caller was
  expanded. Self-edges are dropped and **declared with their reason**; ranges come from the
  M62 address owner and carry the declared unknown where the store holds no real line.
- **Outgoing connected/containment links opened the far end's file at the caller's stored
  line** — a link labelled "instantiates [Greeter]" that opened `greeter.ts:4` when the site is
  `app.ts:4`. Outgoing rows now open the far end's declaration and never turn a stored line
  into a link target for a different symbol.

A new absence code `no_stored_calls` distinguishes "served symbol with an empty call list" from
`symbol_not_at_position`, which was false for it — a machine-readable code a client may branch
on must not contradict the answer.

### The hover's relationship denominator was ten kinds against an index that stores fourteen

`decorates`, `renders`, `mixes_in` and `part_of` were stored, classified by the hover's own tier
owner, and could not be rendered or declared because the denominator and the verb table stopped
at ten. All fourteen now have a denominator entry, both-direction verbs, and — for `part_of` —
a declared absence instead of a link (a module-level inclusion, like `imports`, is not drawn as
a symbol link). The drift gate that catches this was itself anchored on a file the kind
enumeration had moved out of, so it had been reporting a refactor as a pass rather than
checking a fact.

### Warm hover latency: p95 51.31 ms → 9.82 ms

The warm budget is 50 ms (§3). One of three busy shapes missed it. The cause was not the parse:
the hover resolved a full call-site location for **every** row and then discarded it for any row
whose stored call-site line was real, so a 32-file symbol paid 30 file reads and 60 position
mappers per request for positions nothing later read. Now a row with a real stored call-site
line is served from `(caller path, stored line)` validated only by the line-count bound, and
line counts ride a bounded LRU keyed by `(path, mtimeMs, size)` — stat-only on a warm hit,
re-read on any mismatch. Measured with load average 20.67 on 8 CPUs: shape A p50 6.62 ms /
p95 9.82 ms; shapes B and C under 5 ms. No regex was introduced (regex policy: 0 new).

### The extension activated on 7 of the 14 languages the server serves

`src/lsp/launch_languages.ts` is the single owner of the launch set (14 languages), but
`package.json` `activationEvents` and the client's `documentSelector` listed 7. On a Go, Rust,
C, C++, Vue, Svelte or Zig file the extension never activated; in a mixed workspace VS Code
sent no requests for those files at all. Both lists are now derived from the owner through a
type-enforced language-id table, and `esbuild-extension.mjs` fails the build if
`activationEvents` drifts from the launch set.

### The status-bar badge was dead on three paths

Clicking the `bb` badge opened nothing when there was no workspace folder (a single file
opened), when the server was not resolved, or when the server version was incompatible — the
click target was assigned only on the success path. The command is now assigned at creation and
every command is registered before any early return, so no badge renders without a working
click.

### A claim ladder with three definitions

The I0–I5 levels were defined three times and disagreed: the contract said I2
INDEX-CONFORMANT / I3 EDITOR-VERIFIED / I4 FORK-VERIFIED, the extension README said
RUNTIME-PASSED / IN-EDITOR / CROSS-EDITOR, and the status model said HARNESS-VERIFIED /
EDITOR-VERIFIED / PRECISION-VERIFIED. The website rendered two of them side by side. The
contract is governing; both other copies now defer to it and define no second ladder.

### Verification machinery repaired

Six gates were red or silently not running, each for a reason unrelated to the product:

- `verify-relations.ts` M4 anchored on a source expression M62 had moved behind the
  single-owner constant `STORED_LINE_COLUMN`, so it matched zero times.
- `verify-call-hierarchy.ts` C1 asserted a store shape the engine stopped producing in
  `2617ac1bd` ("an unresolved target is reported as unresolved, not matched by name"); it is
  now a hermetic planted-row test, and the seven free verdicts it caused are gone.
- `verify-hover-coverage.ts` V1c read `src/mcp/tool-registry.ts`, where the relationship-kind
  enumeration no longer lives, and its machine metadata shelled out to
  `sysctl -n hw.ncpu`, which crashes on Linux before any result is written.
- `verify-evidence-tree-clean.ts` counted ~6.7k **deliberately gitignored** research artifacts
  as "scratch" while its own self-check asked git the same question and got a different
  answer; and its EVID-TREE claim declared only verifier paths as coverage, so the fingerprint
  could not discriminate and the gate threw on every run that reached the evidence write.
- Four gates (`verify-server`, `verify-usage-scope`, `verify-usages-fallback`) did not pin
  `BB_DATA_DIR`, so on a host with a read-only `~/.bb` every absence-carrier path died with
  `-32603 ENOENT` — a red gate about the sandbox. They now pin a temp data dir unless one is
  supplied, and `L1` is 142/142 reproducibly.

### Documentation and tree hygiene

Documentation now states measured fact rather than narrated decision: the "owner said",
"his words" and "owner live test" framing is gone from the IDE documents and from the
analyzer header template that taught it. Thirteen superseded/duplicate documents and twelve
stray root files (six ad-hoc probes referencing a path that does not exist in this layout, a
certificate log, two XML probes, two superseded root docs, an unused wasm copy) were removed
after a reference grep proved nothing cited them. A new `docs/IDE-LANE-BASELINE.md` records,
per record, what the documents claimed, what the record claimed, what the gate returned at
HEAD, and what is actually true — four different states that had been collapsed into one.

### A `callers` count was not a count of calls

The graph engine's default covers every relationship kind the index stores — documented, and
deliberate, because `contains` is the parent→member edge and excluding it stops a traversal rooted
at a class from reaching that class's own methods. Three consumers in `src/` read that set while
making a claim about one kind:

- `testImpact` published a depth-0 row from a test file as a DIRECT test without asking what kind
  of row it was, so a test class that *contains* the symbol under test answered as a test that
  depends on it — and `testSuggestions` stamped that `direct_call` at 0.85 confidence.
- `testSuggestions`'s `blastRadius`, labelled "caller closure", counted containment and lexical
  rows, and it feeds `priorityFor`, so structure inflated a priority.
- the deprecated `analyzeImpact` (not reachable from any tool since M48) fitted every kind into
  `directSymbols` / `affectedFiles`.

Measured on a fixture whose store holds, from the real analyzer, `realTest --calls--> nested` and
`TestHost --contains--> nested`: the unscoped walk returns both callers, the scoped walk returns
one, and the tool now reports `directTests: [{ testSymbol: "realTest", relationshipType: "calls",
evidence: "direct_call" }]`. `TestImpactReport.directTests` / `indirectTests` and
`AffectedTestEntry` now carry `relationshipType` and `evidence`, so "directly a test" is never
published as "directly calls". `testSuggestions` walks `bb_impact`'s declared dependency rule
(`IMPACT_REL_TYPES`, one list, imported from its owner) instead of every kind.

`bb_analyze`'s page said nothing about the kind set its `callers`/`callees`/`trace` modes walk; it
does now, including that mode `impact` walks the declared dependency rule instead — so a `callers`
count and an `impact` count about the same symbol are not the same question, and both name the rule.
Pinned by `script/m65/verify-edge-kind-scoping.ts`: an inventory of every graph call site in `src/`
(an unscoped one must be a declared all-kinds door), a fixture differential against the store, two
mutations, and source guards so a reverted filter fails the gate.

### The public surface grew from ten to sixteen

The 0.3.0 section below describes that release's surface, and it was accurate when it
was written (2026-08-09). Six tools have been added since, so the live surface is
sixteen — the number is now read from `docs/data/public-tools.json` wherever it is
needed instead of being restated:

- `bb_index` — reindex a file or directory so the index reflects edits immediately,
  plus `mode=post` to re-run derived phases without re-parsing.
- `bb_graph` — per-symbol callers/callees at a declared depth, with per-edge evidence
  tier and confidence from the canonical graph engine.
- `bb_impact` — bounded reverse-dependency impact with a declared node budget and an
  echoed relationship-type rule.
- `bb_cross_language` — stored cross-language facts for one symbol, with absence
  declared rather than inferred when the store holds none.
- `bb_annotate` — write an agent-authored note with `author_class` enforced at the
  schema level, never spoofable.
- `bb_annotations` — read notes back with full provenance and a declared bound.

Same release window, same defect class: `README.md` and both MCP acceptance harnesses
(`script/verify-mcp.ts`, `script/verify-mcp-e2e.ts`) had kept the old count in prose and
in an assertion. The stale assertion failed at command 125 of 358 in `npm run verify`,
which made the 233 commands after it unreachable — so nothing downstream could notice.
Both harnesses now derive the expected surface from the contract file, cover all sixteen
tools (five had no MCP-level test at all, and `bb_index` had never been called as a tool),
and fail with a named missing/undeclared list rather than a bare number.
