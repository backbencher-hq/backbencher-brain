**Milestone:** M57 (#57). Root cause found with evidence during M50.A2 (receipt: `validation/m50/results/A2-test-sources.json`).

## The defect (measured, not guessed)

`src/ast/parallel-indexer.ts` sets `is_test_file` from the lowered relative path only:

```ts
const isTestFile = pathLower.includes("/test/") || pathLower.includes("/tests/") ||
  pathLower.includes("/__tests__/") || pathLower.includes("/spec/") ||
  pathLower.includes(".test.") || pathLower.includes(".spec.") ? 1 : 0
```

No file-type check. Consequences measured on the real index (2,681 files / 168k symbols):
- All **30** files flagged `is_test_file=1` are **JSON data fixtures** (`script/m14/spec/*-completeness.json`, `validation/m14/results/M14.0.SPEC.json`); zero real test files are flagged correctly by intent.
- Every relationship originating in those files is `contains` — **0** call/reference/import edges — so test-intel classified nothing.
- `bb_analyze test_gaps/test_mapping` reported **all 30,557** production symbols as untested from a corpus of JSON; `test_quality` listed 30 JSON files as test files.
- `AnalysisExclusions.isTestPath()` (name-based: `.test.`, `_test.go`, `Tests?` stem, `test|tests|__tests__|spec|specs|e2e` dir segments) **diverges** from the indexer flag — two detectors disagree on the same file.

M50 made the read tools honest (code-only corpus + declared exclusions); this milestone fixes the **source**.

## Acceptance criteria

- T1b. The path-shape rules stay (`.test.`/`.spec.` infixes, test/spec dir segments) and are **aligned with `AnalysisExclusions.isTestPath()`** so exactly one detector definition exists (T5 absorbs the alignment proof).

- T1e. No regression in excluded-path analysis: `analysis-exclusions` gates (M12/M15 pattern corpus expectations) re-run green **after** re-index.
